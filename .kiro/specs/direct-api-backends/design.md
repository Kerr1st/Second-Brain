# Provider request and accounting: design

Role resolution (`resolve_stage`) supplies the invoker and the role specification. `DirectApiInvoker` owns the tool-less template: tools guard, timed provider call, exception mapping onto `TimeoutError`/`RuntimeError`, usage capture before parsing, the shared `parse_json_output` backstop and the per-call metrics line. `BedrockInvoker` owns Converse request shaping (system field, messages, `inferenceConfig`, `toolConfig` for structured output, `additionalModelRequestFields` per vendor, `serviceTier`) and response/usage translation including `reconcile_input_usage`.

`invoke_metered` (`src/backends/cost.py`) checks the route and the threshold before a call, prices real usage from the list-price table (Flex when served on Flex, ceiling for unknown ids), charges known failed responses, reserves for transport failures and blocks continuation when usage cannot be priced. Provider, output-contract and routing failures remain distinguishable to consumers. The Kiro and Codex adapters stay registered for non-corpus use; the laptop and mini compatibility profiles run on Claude Code.

Why a sibling base rather than the CLI template: a direct call has no command, subprocess, temp config or MCP probe, and its timeout is a client read timeout; the two families share only the metrics writer, the parse backstop, usage normalization and the rule that an infrastructure failure always raises. Managed agent platforms and agent SDKs were considered and rejected for this layer (archived requirements, "Considered Alternatives"): the seats are single-shot and tool-less by design, the vote already exists in `consensus.py`, and soft spend caps that terminate silently contradict the fail-loud contract.
