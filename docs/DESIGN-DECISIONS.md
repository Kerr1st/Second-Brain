# Design decisions

These decisions explain the current contracts. The archived plans and research records ([docs/archive/2026-09-26/](archive/2026-09-26/README.md)) preserve their historical rationale without being operating instructions.

1. **Optimize for useful connections.** A discovery must connect evidence to a current problem with an explicit transfer mechanism and adaptation. More records, generic reminders and panel agreement are intermediate signals ([VALIDATION.md](VALIDATION.md)).
2. **Keep raw evidence and derived claims separate.** Source identities, roles, versions and lineage survive ingestion, dedup and discovery. Model proposals cannot overwrite captured evidence or governing instructions; storage authorizes targets deterministically and before any seat is paid.
3. **One transactional storage boundary per logical result.** A source revision and a candidate operation each commit atomically; embedding and model preparation precede mutation; failure preserves earlier complete work.
4. **Combine lexical and vector retrieval.** Full-text search reaches unembedded sources. Synthetic ranking regressions protect code behaviour; held-out user tasks evaluate meaning and benefit.
5. **Keep the four-seat panel while measuring benefit.** Three accepts decide the model review, with two model families on the panel in the controlled profile. It is a heuristic vote: no fault-tolerance guarantee, no confidence update. The grounding audit is a separate call and is hidden from the voting projection.
6. **Enforce capabilities in tools and storage, not prompts.** Deterministic storage authorization is independent of the vote. The read-only MCP registry exists for discovery agents but is not yet attached to the Explorer; until it is, the Explorer's boundary is storage authorization, and that gap is tracked, not papered over.
7. **Account for failed paid calls.** A valid response can be malformed or refused; its usage is billed before retry. A call that fails before any response is charged a conservative reservation so the run stops on the cap rather than looping or blocking. Unknown usage after a successful response fails closed. Thresholds are post-response stops that one call can overshoot.
8. **Preserve specialized capture semantics inside one framework.** Common rendering, windows and outcomes reduce duplication, while Codex task/turn segmentation and retry state stay specialized. CLI-local execution is not model locality.
9. **Retire writers before data, and export before dropping.** The knowledge-graph tables had no reader; their writer was retired in R7 only after a verified encrypted export with a receipt and a ledger marker, and migration 018 refuses to drop populated tables whose counts do not match that marker. Source control is not data recovery; the archive and the pre-window bundle are.
10. **Least privilege at runtime.** Schema ownership and migrations belong to `memory_bank_owner`; jobs and MCP servers run as `memory_bank` with DML only. The demotion of the application role is an explicit operator step with an immediate reversal, not a side effect of a migration.
11. **Truthful operations.** One job runner, one lock, one deadline and one durable status per job; a running process with no useful output is unhealthy; PostgreSQL is never auto-started by a job; a dark-wake launch waits for the network instead of failing on the first Bedrock call.
12. **Qualify source, operation and effectiveness separately.** Offline tests, restored-dump rehearsals, live provider probes, deployment records and human outcomes each establish different facts. [RELEASES.md](RELEASES.md) records the exact boundary reached.
