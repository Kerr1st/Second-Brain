# Glossary

Alphabetical definitions of project-specific terms used throughout the Second Brain documentation.

| Term | Definition |
|------|------------|
| **agent** | An AI assistant (Kiro, Amazon Quick, Amazon Q Developer, Claude Code, Codex, or another supported assistant) connected to Second Brain. Agents can contribute captured tasks and read or write memories through supported interfaces. |
| **Agent Task** | One source-defined unit of work or conversation from an agentic assistant, normalized into Second Brain's shared capture model. |
| **Agent Turn** | One complete prompt-outcome exchange within an Agent Task. It contains the user's prompt and the agent's visible outcome, not hidden reasoning, tools, or progress activity. |
| **Amazon Bedrock** | The AWS service that provides embedding generation (Titan v2, 1024 dimensions) and LLM inference for Second Brain. |
| **Amazon Q Developer** | Amazon's developer-focused assistant and agentic coding environment. It is separate from Kiro and Amazon Quick. |
| **Amazon Quick** | Amazon's web-based work assistant and agent platform. Its sessions are a separate capture source from Quick Desktop sessions. |
| **Applicability** | The integrations, semantic projects, repositories, topics, tools, languages, or paths in which a Steering Rule is relevant. It is separate from Authority Scope. |
| **Attachment Descriptor** | A non-content audit record that an image or file accompanied an Agent Turn. It preserves available source metadata without retaining or interpreting the attachment itself. |
| **Authority Scope** | The owner of a Steering Rule: one project, the user personally, or the Second Brain system. It is reviewed separately from Applicability before a rule becomes active. |
| **capture** | The first pipeline stage: content enters the system from channels such as Kiro CLI chats, Quick Desktop, YouTube transcripts, or web articles. See [overview](overview.md). |
| **Captured Task** | Second Brain's durable, append-only representation of one Agent Task and its ordered Agent Turns. |
| **chunk** | A unit-sized piece of content produced during ingestion, suitable for embedding and storage as a single memory. |
| **consensus panel** | The four evaluators (Skeptic, User Advocate, Epistemologist, Methodologist) that independently vote ACCEPT or REJECT on each dream cycle candidate. ≥3/4 votes required for acceptance (BFT). |
| **Correction Episode** | Episodic evidence that the user rejected, replaced, or materially narrowed a prior visible agent outcome and stated a specific improved expectation. It preserves the narrowest faithful version of the user's correction, cites both supporting Agent Turns, remains searchable and available to the Dream Cycle, and is not itself a Steering Rule. |
| **Delegated Task** | An Agent Task created by an agent as child work inside another task. It is excluded from independent capture because its useful outcome may already appear in the User-Owned Task. |
| **depth score** | A 0.0–1.0 rating of how substantive a memory's content is. Memories of type `idea`/`synthesis`/`insight`/`decision` with depth < 0.3 trigger a warning at creation time. |
| **dream cycle** | The daily autonomous synthesis pipeline that runs Explorer → Thinker → Consensus Panel to produce accepted insights from existing memories. See [reference](reference.md). |
| **embedding** | A 1024-dimensional vector representation of a memory's content, generated by Amazon Bedrock Titan v2 and stored in the `memories.embedding` column for vector similarity search. |
| **episodic memory** | A `mem_class` value. Raw logs, source transcripts, and session records — concrete events anchored in time. Receives no rerank boost. |
| **Exact Provenance** | The traceability chain from a derived memory through its supporting Agent Turns to the original Agent Task. Model versions, hashes, timings, and usage telemetry are processing diagnostics, not provenance. |
| **Explorer** | The first dream cycle agent. Assembles "memory slices" using strategies such as temporal juxtaposition, cross-project collision, and orphan archaeology. |
| **Express** | The delivery subsystem that surfaces synthesized knowledge to you — via the `brief` CLI command, a gated Gmail push, the `memory_brief` MCP tool, and a feedback loop. See [reference](reference.md). |
| **hybrid search** | The retrieval strategy combining BM25 full-text search and pgvector cosine similarity, fused with RRF, then reranked. |
| **ingestion** | The second pipeline stage: content is parsed, classified, chunked, embedded, stored, and auto-linked to related memories. |
| **Kiro** | An agentic coding service with IDE, CLI, and web surfaces. It is separate from Amazon Quick and Amazon Q Developer. |
| **launchd job** | A macOS scheduled task defined by a `.plist` file. Second Brain uses launchd for the dream cycle, Express push, backup, and sync jobs. |
| **MCP server** | The Model Context Protocol server (`src/mcp_server.py`) exposing 9 tools that agents invoke to read and write the memory store. See [reference](reference.md). |
| **memory** | The atomic unit of the system: text content, a vector embedding, metadata (type, tags, source, confidence), and relationships to other memories. Stored in the `memories` table. |
| **memory class** | One of three classifications per Tulving's taxonomy — `semantic` (facts, principles), `episodic` (raw logs, events), or `procedural` (how-to knowledge). Stored in `mem_class`. |
| **memory type** | A label describing what a memory represents, including `research`, `synthesis`, `idea`, `connection`, `priority`, `question`, `insight`, `decision`, `correction_episode`, `project`, and `source`. See [reference](reference.md). |
| **Monotonic Task Refresh** | A refresh that preserves captured Agent Turns in their original order and appends only unseen complete turns. It never rewrites established task evidence. |
| **pgvector** | A PostgreSQL extension that adds vector data types, HNSW and IVFFlat indexes, and distance operators. Enables vector similarity search on embeddings. |
| **procedural memory** | A `mem_class` value. How-to knowledge, workflows, and step-by-step processes. Receives a +0.02 rerank boost. |
| **Quick Desktop** | A desktop agent application with its own local session storage. It is separate from Amazon Quick; its documents, sessions, feed events, and Slack cache are synced into Second Brain, and its imported knowledge-graph tables are currently **dormant**. |
| **relationship** | A typed, directed edge between two memories (e.g., A `supports` B). Stored in `memory_relationships`. The 9 types are listed in [reference](reference.md). |
| **reranking** | The scoring pass applied after hybrid search fuses BM25 and vector results. Incorporates token overlap, recency, depth, memory class boost, retrieval reinforcement, project penalty, and other signals. |
| **retrieval reinforcement** | The mechanism that strengthens frequently-accessed memories: `access_count` is incremented and `last_accessed_at` updated on each retrieval, feeding a spaced-retrieval bonus into reranking. |
| **RRF (Reciprocal Rank Fusion)** | The algorithm that merges BM25 and vector search result lists into a single ranked list: `score = 1/(k + rank_vec) + 1/(k + rank_bm25)`, with k=60. |
| **semantic memory** | A `mem_class` value. Facts, principles, decisions, and insights — abstracted knowledge independent of when it was learned. Receives a +0.04 rerank boost. |
| **Semantic Processing Cursor** | The last Agent Turn included in a successfully stored Task Semantic Pass. Later turns constitute the unprocessed tail. |
| **Semantic Project** | The real-world subject to which a memory belongs. Source-native projects, workspaces, and repositories are preserved as provenance but are not automatically copied into `memories.project`. |
| **Source Drift** | A readable source observation in which a previously captured Agent Turn changed, disappeared, or moved. The monotonic capture policy ignores it without rewriting stored evidence or recording additional capture state. |
| **source_type** | A field on `memories` identifying the capture channel (e.g., `youtube`, `article`, `kiro_cli_chat`, `kiro_ide_chat`, `distilled_chat`, `quick_desktop_doc`, `quick_desktop_chat`, `quick_desktop_feed`). |
| **Steering Candidate** | A proposed reusable behavioral rule inferred from one or more Correction Episodes. In the deferred Build 2 design, the Thinker proposes it and the four-evaluator panel must accept it before user review; it remains inactive until the user approves its wording, Authority Scope, and Applicability. |
| **Steering Rule** | A user-approved behavioral instruction derived from accepted correction evidence. Unlike a Correction Episode, it has authority and may be placed into agent steering context within its approved scope and applicability. |
| **superseded** | A memory status indicating it has been replaced by a newer version. The old memory keeps a `superseded_by` relationship to the replacement. Superseded memories receive a −0.20 rerank penalty. |
| **Supersession Candidate** | A deferred Build 2 proposal that materially refines or contradicts an existing Steering Rule. It preserves the old rule and requires the same evaluation and user-approval path as other steering changes. |
| **Task Distillation** | The extraction of task-level decisions, insights, and Correction Episodes from a Captured Task's Topic Segments, before higher-order Dream Cycle synthesis. |
| **Task Ownership** | A Source Connector's evidence-based classification of an Agent Task as `user-owned`, `delegated`, or `unknown`. Only User-Owned Tasks are eligible for independent capture. |
| **Task Semantic Pass** | One combined interpretation of a newly captured task tail that returns Topic Segments and zero or more supported decisions, insights, or Correction Episodes for each segment. It does not require a separate segment summary. |
| **Thinker** | The second dream cycle agent. Analyzes Explorer's memory slices and proposes candidate insights with operations (CREATE, UPDATE, SUPERSEDE). |
| **Topic Segment** | A contiguous range of complete Agent Turns that develops one coherent subject enough to stand alone for search or distillation. Brief asides remain with their surrounding segment. |
| **Unknown-Ownership Task** | An Agent Task without reliable native evidence establishing whether it is user-owned or delegated. It is skipped and reported. |
| **User-Owned Task** | An Agent Task that native source evidence identifies as a conversation initiated for the user. |
