# Purpose and implementation history

The purpose is to capture work context across surfaces and discover connections that improve an actual decision, plan or deliverable. The user specifically wants prior projects' outcomes to inform current work, with sources and enough context to make the transfer useful. A reminder to follow up is insufficient unless the discovery explains which decision it bears on, why it matters and how the mechanism helps.

The original implementation (spring 2026) stores memories in PostgreSQL/pgvector, captures source channels, distills selected conversations, retrieves evidence, runs a multi-seat dream cycle and delivers briefings. A separate experimental GitHub implementation explored repairs and alternate structure in development environments; it was never a deployed replacement and is not part of this tree. The documents of that period are preserved verbatim under [docs/archive/2026-09-26/](archive/2026-09-26/README.md) and, in their 2026-09-10 generalized form, under [docs/archive/2026-09-10/](archive/2026-09-10/README-ARCHIVE.md).

A 35-record comparison in September 2026 produced candidate ideas through model roles with frozen evidence. It did not run complete native capture, distillation, retrieval, persistence, delivery or observed user outcomes; its useful suggestions were evidence to investigate, not proof that the system met its purpose.

The audits of 2026-09-23/24 ([AUDIT-2026-09-24.md](AUDIT-2026-09-24.md), [findings register](audit-2026-09-24/00-FINDINGS-REGISTER.md)) and the refactor plan ([PLAN-refactor.md](PLAN-refactor.md)) chose to repair reliability before changing the reasoning architecture: controlled routing and accounting, source integrity, deterministic candidate authorization, truthful operations, encrypted recovery, measurable retrieval, least-privilege database roles. The refactor branch of 2026-09-26 implemented that plan in one tree; its ledgers are archived under [docs/archive/refactor-2026-09-26/](archive/refactor-2026-09-26/README.md). It was then re-cut into the reviewed release line R1 → R3 → R4 → R5 → R7 described in [RELEASES.md](RELEASES.md), each release rehearsed against a restored production dump before its runbook was written.

What has not happened yet: the paid corpus repair (R6), the human evaluation trial that would compare ordinary retrieval with discovery on a live decision, and the credential and key-custody closures listed in [PLAN-refactor.md](PLAN-refactor.md). Human novelty and outcome remain distinct from a model's vote; nothing in this repository certifies that the system has improved the user's work.
