Its content was re-cut from the installed `main` into a chain of small releases, each re-reviewed, each with its own isolated-suite result, rehearsal and runbook. The chain is linear and fast-forward only: `1071a81` (installed until 2026-10-05) → R1 `8dd3bb7` → R3 `e1cff5c` → R4 `d063543` → R5 `0302f0f` → R7 `e5d0d9a`, all deployed on 2026-10-09, followed the same day by the R6 corpus repair. The private review notes (release notes, independent reviews, suite logs, rehearsal evidence, deployment records) live outside this repository in the operator's review folder; the file names are given so a reader can ask for them. They are not committed because they contain host paths, counts over the private corpus and operator decisions.

Status vocabulary: **built** = commits exist and the isolated suite passed twice at the head; **reviewed** = an independent read-only review was answered in follow-up commits; **deployed** = the installed checkout's `main` was fast-forwarded and the jobs restarted, with a deployment record; **pending authorization** = a procedure exists but its paid or irreversible step waits for the operator; **applied** = an operational release (no code) whose authorized steps were run against production, with a deployment record. Deployment records `R3-DEPLOYMENT.md` … `R7-DEPLOYMENT.md` live in the operator's private review folder. A later release assumes every earlier one is deployed; the runbooks hard-gate on the installed `HEAD` and the migration ledger.

## R1 — routing and spend foundation (`8dd3bb7`, deployed 2026-10-05)

Base `bf854cd` plus nine commits. `controlled` becomes the default profile; corpus roles can never resolve to Kiro or a model whose id contains `fable`; every reasoning call goes through `invoke_metered` with a `SpendTracker`. Live-damage fixes: relationship expiry respects age and access grace and never expires provenance edges; the nightly backup stops `rclone sync`ing the knowledge sources and config to Google Drive in plaintext; liveness tests read `DB_HOST`/`DB_PORT` from the environment so the suite can no longer touch production. Spend policy: a call that fails before any response exists is charged a conservative reservation instead of blocking the run; implausible Bedrock input counts are reconciled before pricing; evaluator seats carry explicit `max_tokens`. No schema change. Deployment record: 13:30–14:08 PDT, fast-forward from `1071a81`, 16 labels re-bootstrapped, `distill` left disabled, zero model calls. The pre-R1 dirty working tree (Sep-10 documentation stubs and backend edits) is preserved as the branch `preserve/2026-09-10` @ `50ac872`; its documents are archived under [docs/archive/2026-09-10-installed/](archive/2026-09-10-installed/README-ARCHIVE.md).

## R3 — data layer (`e1cff5c`, deployed 2026-10-09)

Thirteen commits. `src/db.py` becomes the `src/db/` package (pool, columns, memories, relationships, capture, search and express queries, maintenance); the dream-cycle orchestrator is decomposed into agents, stages and repositories while keeping the R1 policies; migration `016_data_integrity.sql` (lock timeout, source vocabulary CHECK, relationship permanence CHECK, `cost_usd`, `corpus_maintenance` ledger, index repairs, un-expiry backfill under the R1 rule) ships with the code that depends on it. Fixes from the review: capture identity is channel + URL, CLI sessions are no longer tagged with their UUID as project, digests and SIGTERM never leave a judged run aborted, candidates are authorized before spend, FTS excludes parents with active chunks, embedding inputs are bounded, `ingest_batch` keeps per-item resilience, 016 is re-runnable after a restore-based rollback, `memory_read` no longer ships `search_vector`. R3 is the one release that needs a maintenance window (quiesce → verified backup → fast-forward → 016 → smoke → bootstrap); rollback is a restore of the pre-window dump. Rehearsed on a restored production dump. Deployed 2026-10-09 16:58 with migration 016 (`R3-DEPLOYMENT.md`).

## R5 — operations (`0302f0f`, deployed 2026-10-09)

Fourteen commits on R4, rebased onto R4's final commit. `scripts/jobs/job_wrapper.sh` → `python -m src.operations.jobs`: per-job lock, deadline with floors, SIGTERM → grace → SIGKILL, durable status under `logs/jobs/`, service mode with health probes for capture-api, network preflight for dark-wake launches (the root cause of the chronic Monday weekly-digest failure), `ExitTimeOut=150` on all 17 plists, PostgreSQL never auto-started by a job (exit 69). Liveness becomes policy-driven (`config/liveness.toml`: required and advisory channels with reasons, generic zero-output rule, dream-cycle freshness, job status sweep). Backups become one encrypted bundle per night (`scripts/maintenance/backup_bundle.py`, `config/backup.toml`): database dump + repository + `.env` + knowledge sources, decrypt-verified before publishing, uploaded and read back, retention 7 d local / 30 d remote, weekly verify with a full restore into a throwaway cluster and a 36 h freshness check. `codex-canary` deleted. Installed plist copies become symlinks in the deploy window. See [OPERATIONS.md](OPERATIONS.md), [DISASTER-RECOVERY.md](DISASTER-RECOVERY.md), [scheduling/README.md](../scheduling/README.md). Deployed 2026-10-09 18:52 (`R5-DEPLOYMENT.md`).

## R6 — paid corpus repair (operational, applied 2026-10-09)

No code: R3 ships the planners and appliers (`scripts/maintenance/prepare_release.py --apply-manifest` for the historical UUID project tags, `dedup_corpus.py` for proven duplicate source identities, `rechunk_and_embed.py` for oversize and tail rows, half-written parents and unembedded leaves). Every apply step takes a reviewed, target-bound manifest and its SHA-256; paid embedding additionally needs `--allow-paid-embedding`. The manifests must be regenerated after R4's first capture runs, priced on the current corpus, and applied in a separate authorized step with the pre-window bundle as the rollback point. The last restored-clone rehearsal (2026-09-26) priced the rechunk at roughly $2–$21 depending on the pricing scenario. Applied to production on 2026-10-09: metadata normalization 2,832 operations, dedup 70 operations; rechunk applied 2026-10-09 (8,240 operations, 96,331 Titan embedding calls), its completion confirmed separately by the deployer in `R6-DEPLOYMENT.md`.

## R7 — cleanup (`release/r7-cleanup` @ `e5d0d9a`, deployed 2026-10-09)

Deployed 2026-10-09 19:30 with migrations 017 and 018 and the application role demoted to `NOSUPERUSER` (`R7-DEPLOYMENT.md`). Reviewed 2026-10-06 (`R7-REVIEW.md`): the database half was approved as built; the documentation half was returned for the missing archived Sep-10 `README.md` and three stale sentences, answered in the follow-up commits listed in `R7-RELEASE-NOTES.md` §1.

Database half: migration `017_role_separation.sql` creates `memory_bank_owner`, which owns the database, every relation and the `vector` extension, and grants the application role DML only (plus default privileges for future owner-created objects); `migrate.sh` refuses to run as anything but the owner (the single bootstrap run as the still-superuser `memory_bank` excepted); `reindex_embedding.sh`, `dedup_ide_backfill.sh` and `cleanup_duplicate_sources.py --apply` do their DDL/VACUUM as the owner. The demotion `ALTER ROLE memory_bank NOSUPERUSER` is a separate operator step, verified by `scripts/maintenance/smoke_app_role.py` (read-only application paths, one rolled-back write, structural refusals). `scripts/maintenance/export_graph_tables.py` writes an encrypted, verified export of `entities`, `entity_edges`, `memory_entities` with a receipt and a `corpus_maintenance` marker; migration `018_retire_knowledge_graph.sql` drops the three tables only behind a marker whose row counts match. The Slack graph writer, the QD `graph` stage, `import_slack_graph.py` and every reader of the graph tables are removed; a repository pin test keeps them out. `_referenced_chunks` batches the superseded-chunk reference check. Isolated suite 2,228 passed twice at the database head; two rehearsals on a restored production dump (017 ≤ 1.2 s, export 1.1 s, 018 ≤ 1.4 s, zero permission errors as the demoted role).

Documentation half (this tree): the September-26 documentation layout replaces the June documents; drifted plans, the user guide and nine spec families are archived verbatim under [docs/archive/2026-09-26/](archive/2026-09-26/README.md), the pre-stub snapshot under [docs/archive/2026-09-10/](archive/2026-09-10/README-ARCHIVE.md), the installed Sep-10 working-tree versions under [docs/archive/2026-09-10-installed/](archive/2026-09-10-installed/README-ARCHIVE.md), and the refactor branch's own ledgers under [docs/archive/refactor-2026-09-26/](archive/refactor-2026-09-26/README.md). Every current guide was re-pinned to the R7 code. `docs/generated/runtime-inventory.md` is produced by `scripts/docs/inventory.py` and checked by `tests/test_repo_hygiene.py`, which also checks the owned-hazards table in [VALIDATION.md](VALIDATION.md) and keeps personal identifiers out of the live documents.
