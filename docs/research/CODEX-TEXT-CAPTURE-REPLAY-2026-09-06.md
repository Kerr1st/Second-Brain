# Codex text capture fix: isolated replay

The proposed source-reader change captures the eight completed exchanges that
previously yielded zero Agent Turns. This establishes a capture compatibility
fix for the recorded text sample. It does not establish improved downstream
answers or completion of the full Second Brain lifecycle.

## Comparison and isolation

The failed baseline used the source reader at `5335d808` on 2026-09-05. Its
recorded source SHA-256 was:

```
a54664887da09bc7640cfa05494cd0414b04738aad30097e2f668bbec21c340a
```

For the 2026-09-06 replay, the identical 415-record prefix was recovered from
the append-only native rollout and verified against that hash. Its eight
completed exchanges exclude the later discussion and implementation of this fix.
The original record bytes and timestamps were preserved in a private local
snapshot; no expected answers or substitute memories were inserted.

The replay supplied that snapshot to the source reader and selected only its
native task identity. It used a fresh `second_brain_eval_*` database, the real
migration runner, the real capture and semantic persistence code, the configured
`codex_local` thinker (`gpt-5.6-sol`, effort `max`), and local BGE-M3 embeddings.
The private runner substituted the source location, conservative last-activity
observation, display title, database target, and evaluation lock location.
Native ownership was still checked against the local task index.

As in the failed baseline, the supplied evaluation clock was
`2026-09-05T22:34:01.500000+00:00`: six hours and one second after the snapshot's
last observed activity. This is controlled replay after eligibility, not
observation of the automatic hourly scheduler. The host clock, native rollout,
operational checkout, job configuration, and live memory database were not
changed by the replay.

## Observed results

| Check | Original reader | Proposed reader |
|---|---:|---:|
| Completed native exchanges in the sample | 8 | 8 |
| Normalized Agent Turns | 0 | 8 |
| Captured source tasks | 0 | 1 |
| Successful Task Semantic Passes | 0 | 1 |
| Stored Topic Segments | 0 | 2 |
| Derived memories | 0 | 4 |

Every normalized prompt and final answer was compared with its exact native
text. Each turn retained the native authored message ID. All supporting turn
references in the four derived memories resolved to those captured turns.
Database readback found four provenance relationships and six embedded rows
(two segments and four derived memories); the source parent was retained
without an embedding, as the existing pipeline specifies.

A second capture of the same snapshot returned `unchanged=1`,
`semantic_processed=0`, and `failed=0`: it did not duplicate the source or repeat
semantic processing. Both invocations completed without capture failures.

The semantic output was generated by the existing prompt and model configuration.
These counts and valid references establish mechanical processing and traceability,
not a human-validated assessment of every distilled claim. Dream Cycle selection,
fresh-task retrieval, comparative answer quality, and outcome reporting were not
run in this increment. The isolated database contained zero context receipts.

## Regression coverage and limits

The committed real excerpt initially failed with `0 != 1` turns against the old
reader. The original full replay also caught an overly conservative intermediate
implementation that treated injected environment metadata as unsupported user
input; that case now has explicit regression coverage.

The final full suite passed **900 tests**, with one existing Starlette/httpx
deprecation warning. Coverage includes the verified current text shape,
injected context with and without metadata, invalid/unsupported prompts,
matching finals, multiple authored prompt parts, duplicate message IDs,
interrupted executions, legacy mirrors, old history resumed in the current
format, and database persistence with idempotent repeat capture.

This extension intentionally does not infer support for current-format images,
files, voice messages, or undocumented authorship shapes. Existing legacy image
descriptors continue through the original event path. No eligibility, semantic
prompt, storage schema, or steering approval behavior was changed.

Reproduce the bounded committed-fixture check with:

```bash
python -m pytest tests/test_codex_capture.py -k current_native_authored -q
```

The private full-source snapshot, replay script, database identifier, results,
and test output remain under the ignored
`evaluations/results/2026-09-06-capture-fix/` directory. Raw evaluation history
and derived memory contents are not included in this report or the PR.
