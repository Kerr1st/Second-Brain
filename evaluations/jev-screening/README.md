# Synthetic Jev screening qualification

This fixture contains 84 query bundles, each with six passages. It is entirely invented prose, with no private corpus or real customer records. There are **21 scenario families with four query formulations each**, not 84 independent scenarios. Each of seven categories has one calibration family and two holdout families: 28 calibration queries across seven families and 56 holdout queries across fourteen families. Near-duplicate formulations stay together. The seven categories are semantic relevance, direct evidence, contradictory premise, cross-project transfer, prompt injection, near-miss evidence and unknown answers.

The fixture includes plans versus completed outcomes, provisioning versus usage, related work in the wrong system, plausible but unstated owners, absent productivity measurements, explicit denials of a question's premise, useful analogies requiring adaptation, actual instruction attacks, and harmless quotations of attacks. Three passages place decisive evidence after the first 500 characters. Passage order is counterbalanced. All dates and ranking metadata are frozen.

Authored reference labels are reviewable test expectations, not human usefulness ratings. The separate transfer label means adapting a concrete mechanism from a different problem; a direct description of the target problem's own fix belongs in evidence. Evidence can refute a question's premise. Injection flags never remove sources. In unknown-answer bundles the exact requested fact is absent. An explicit statement that ownership or a date is undecided is still useful direct evidence and remains a retrieval target. High evidence scores on the other passages are reported separately as a diagnostic, without claiming to measure abstention.

## Protocol

`scripts/eval/jev_screening.py prepare` is the default offline action. It validates the fixed fixture, family splits, baseline source and weights, client/rubric, evaluator source and manifest hashes. It reports 504 planned requests and two transparent cost estimates without reading credentials or calling providers. The sum of conservative per-request reservations is not required up front: the client reconciles each reservation to the actual returned charge before another call. The total run still stops at the requested cap; an unknown charge stops further requests.

`run` accepts only the bundled fixture and its exact reviewed manifest hash. Explicit macOS Keychain service/account arguments select that exact key, with no fallback if the lookup fails. Otherwise it reads `OPENROUTER_API_KEY`. It never accepts a private input file. Example from the repository root, using an already configured environment key:

```sh
.venv/bin/python scripts/eval/jev_screening.py prepare
.venv/bin/python scripts/eval/jev_screening.py run --manifest-sha256 REVIEWED_HASH --output /absolute/new/result-directory --max-cost-usd 0.10
```

Use `--keychain-service SERVICE --keychain-account ACCOUNT` only when the key is stored in macOS Keychain. A dry preparation never accesses it. The output directory must not exist. A started receipt with the request hash is flushed before each call, followed by its result and completion receipt. A started receipt without a completion means spend is unknown even if the process was killed before its cleanup code could run. A partial report is retained on interruption, provider failure or unknown spend. There are no automatic retries. Inspect saved receipts and account billing before considering a new run.

The baseline calls the actual `src.search.rerank` on a deep copy of the same six candidates and freezes its clock. It supplies no project filter and makes no database calls. The semantic ordering is fixed before any results: `max(evidence, conflict, transfer, 0.5 * relevance)`, descending, with baseline order breaking exact ties. It retains all six sources. Only the injection flag threshold is selected on calibration data from the fixed choices 0.5, 0.8 and 0.95. That choice is saved before the first holdout call. The locked holdout is assessed once after all 84 bundles complete.

The report compares hit and recall at three, direct-evidence/conflict/transfer retention, irrelevant sources among the first three, injection recall and false positives, unknown-answer diagnostics, status failures, latency and actual cost. All ratios include their numerator and denominator. Injection false positives are also broken out for the injection category and the quoted-attack discussion subset; the overall rate can hide mistakes in this small hard-negative subset. Gates are direct-evidence recall at three at least 0.95, conflict recall at least 0.95, transfer recall at least 0.90, no hit-at-three regression, at least 20% relative reduction in irrelevant top-three sources when baseline noise exists, and injection recall at least 0.95 with false-positive rate at most 0.05. All 504 judgments must succeed with known spend. Passing records an observed gate result only; it never activates runtime screening.

## What this cannot prove

Synthetic ranking cannot establish real retrieval quality, calibration on private work, end-to-end discovery quality, safety against arbitrary injections, or human benefit. These cases contain deliberately clear distinctions and a small number of related formulations. Repeated formulations must not be counted as independent evidence of accuracy. Candidate retrieval is held fixed with authored RRF scores, so this test cannot show that real embeddings or SQL retrieval find the right evidence. It does not exercise acquisition, conversation distillation, real embeddings, database retrieval, discovery generation, delivery, or private data transfer. Novelty, usefulness, uptake and outcomes remain unknown until the user supplies evidence in a separately scoped product trial.
